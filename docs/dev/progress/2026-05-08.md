## Stage 1 当前改动

- Task surface cutover 已完成 Stage 1 验收收口：
  - `lib/nex/agent/capability/cron.ex` 已迁移为 `lib/nex/agent/tasks.ex`，模块名改为 `Nex.Agent.Tasks`，初步 public API 为 `list/get/upsert/delete/enable/run_now/status`。
  - 新增 `lib/nex/agent/tasks/store.ex`，负责 `tasks/tasks.json` 路径和一次性 `tasks/cron_jobs.json -> tasks/tasks.json` 迁移。
  - 新增 `lib/nex/agent/tasks/projector.ex`，开始提供 `Runtime.Snapshot.tasks` projection。
  - `Runtime.Snapshot.tasks` 已接入 `Tasks.Projector.runtime_data/1`，workspace `tasks/tasks.json` 与 plugin `contributes.tasks` 进入同一 projection。
  - `lib/nex/agent/interface/workbench/tasks.ex` 已替代旧 scheduled tasks surface，HTTP 路由固定为 `/api/workbench/tasks`。
  - Workbench bridge methods 已迁移为 `tasks.list/status/upsert/delete/enable/disable/run`。
  - `lib/nex/agent/runtime/plugin_job_runner.ex` 已删除，runtime hook 后台动作入口迁移为 `Nex.Agent.Tasks.Runner` 和 `plugin.task.*` observations。
  - `plugin.task.*` observations 已使用 `task_run_id`，不再输出旧 `job_id`。
  - `lib/nex/agent/capability/hooks.ex` 已把 plugin hook action 改为 `enqueue_task`。
  - `lib/nex/agent/extension/plugin/contribution.ex` 已把 manifest contribution key 从 `jobs` 改为 `tasks`。
  - `lib/nex/agent/app/infrastructure_supervisor.ex` 已改为启动 `Nex.Agent.Tasks` 和 `Nex.Agent.Tasks.Runner`。
  - `priv/plugins/builtin/workflow.personal-task` 已改用 `Nex.Agent.Tasks` 安排 due/follow-up reminders，并把个人任务数据移到 `tasks/personal_tasks.json`，避免和 runtime task truth source 冲突；提醒关联字段写回为 `reminder_task_ids`。
  - `priv/plugins/builtin/tool.cron` 已删除，不再向 model/tool registry 暴露 `cron` 工具。
  - Task runner tool surface 已从 `:cron` / `definitions_cron` 收口为 `:task` / `definitions_task`；Runner、Tool.Registry、Runtime snapshot、Subagent profile、core tool/plugin manifests 和对齐测试已同步。
  - `lib/nex/agent/observe/admin.ex`、gateway/heartbeat service status、Workbench shell/server tests 已迁到 Task 命名。
  - scheduled task inbound path 已改用 `_from_task` metadata，避免旧 `_from_cron` 入口继续驱动运行时行为。
  - `Nex.Agent.Tasks.Store` 保留一次性 legacy `tasks/cron_jobs.json` 迁移读取；runtime 不再双读双写旧文件。
  - `Nex.Agent.Tasks.upsert/2` 支持 atom/string keyed attrs，并会把 JSON/string schedule shape 规范化为内部 atom schedule。
  - Workbench task source、Admin runtime task projection、onboarding migration helper/log、sandbox/bash metadata 已统一到 task 命名。
