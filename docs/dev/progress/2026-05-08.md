## Stage 3 当前改动

- streamable HTTP MCP transport 已完成 Stage 3 验收收口：
  - 新增 `Nex.Agent.Interface.MCP.Transport.StreamableHTTP`，通过 `Nex.Agent.Interface.HTTP.post/2` 向单一 MCP endpoint 发送 JSON-RPC POST。
  - POST request 固定带 `Accept: application/json, text/event-stream` 和 `Content-Type: application/json`，并在 initialize 后对后续请求带回 `MCP-Session-Id`。
  - MCP initialize protocol version 已对齐本 phase 阅读的官方 `2025-11-25` transport spec。
  - 支持普通 `application/json` response 和 POST `text/event-stream` response，SSE 中会跳过非目标消息并取匹配 request id 的 JSON-RPC response。
  - `MCP.Client` 支持 `transport: "streamable-http"`，且 pending request 在调用 transport 前登记，避免同步 HTTP transport 回包早于 pending 记录的竞态。
  - `ServerManager` / `ToolRegistry` 仍只走统一 MCP facade，不按 stdio/HTTP 分支；review 后修复 plugin MCP call opts 可能是 map 时的审批上下文读取，并让 `Tool.Registry` 把 runtime snapshot config 传入 MCP approval metadata，避免 `ServerManager` 回退读取全局 runtime。
  - review 后收紧 HTTP header normalization，非法非标量 header 值会在 transport init 边界失败，不会被 `inspect` 成日志/diagnostic 明文。
  - plugin `mcpServers` 可声明 `transport` / `url` / `headers` / `timeout_ms` 并通过 runtime reconcile 启动；manifest 不自动授予 network 权限。
