# 2026-05-07

## Plugin Runtime And File Memory Design

- 新增设计稿 `docs/dev/designs/2026-05-07-plugin-runtime-extension-primitives.md`。
  - 明确后续插件系统补强应提供通用 primitives，而不是新增 memory 专用 contribution kind。
  - 收敛 primitives：workspace artifacts、context contributions、LLM-facing capabilities、resources、services、events、queues/jobs/schedules、permissions、observability、migrations。
  - 明确 `ContextBuilder` 长期应降级为 context renderer，不再硬编码 `memory/MEMORY.md`。
- 新增设计稿 `docs/dev/designs/2026-05-07-file-memory-plugin.md`。
  - 将内置文件记忆系统描述为普通 `builtin:memory.files` 插件。
  - 最小 workspace 结构为 `memory/INDEX.md` 和 `memory/INBOX.md`。
  - LLM 侧第一版只暴露 `memory__write` 和 `memory__read`。
  - 记忆整理依赖未来通用 plugin queue/job/event primitive，不继续扩大 `MemoryUpdater` 特例。
- 更新 `docs/dev/designs/index.md` 收录两份设计稿。

## Hindsight Memory Plugin Design

- 新增设计稿 `docs/dev/designs/2026-05-07-hindsight-memory-plugin.md`。
  - 将 Hindsight 定位为 derived memory plugin，不替代 NexAgent 本地 session/event/file raw truth source。
  - 设计 Cloud MCP single-bank / multi-bank、local service、direct REST 接入边界，第一版推荐 Cloud MCP single-bank manual mode。
  - 明确接入所需通用 primitives：MCP client、secret refs、bank scope resolver、resource namespace、dynamic context、queues/jobs、operation tracking、permissions、observability。
  - 默认不启用 auto retain / auto recall，先以显式 tool + skill 验证质量、成本和隐私边界。

## 下一步

- 先把 plugin runtime extension primitives 提升成 task-plan，补齐通用贡献类型和 runtime projection。
- 再基于这些 primitives 实现 `builtin:memory.files`，迁移掉 `ContextBuilder` 对 `memory/MEMORY.md` 的硬编码。
- Hindsight 接入应排在 MCP client / secret / operation tracking primitive 之后，不抢在基础能力前硬写专用 wrapper。
