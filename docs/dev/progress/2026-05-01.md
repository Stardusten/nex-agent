# 2026-05-01

## Runtime fail-soft projection hardening

- Root cause: a workspace skill copied from a remote source used valid YAML `description: >-`, but `Skills.Loader` only accepted bare `>` / `|` block scalar headers. Runtime watcher crashed during skill reload instead of skipping the bad skill.
- Fixed `Skills.Loader` to:
  - parse `>` / `|` block scalar headers with optional `+` / `-` chomp indicators
  - skip a single invalid `SKILL.md` with a warning instead of failing the whole catalog
  - require model-facing `name` and `description` metadata to be strings
- Hardened `Runtime.Watcher` so skills/tools/runtime reload callbacks are isolated; callback failure logs a warning and the watcher keeps polling.
- Hardened `Runtime.build_snapshot/3` so non-critical projections use fail-soft fallback:
  - plugins
  - commands
  - subagents
  - skills
  - tool definitions by surface
  - hooks
  - Workbench app catalog
- Kept config/workspace resolution and prompt build as strong dependencies. Prompt remains the safety/identity-critical model input; prompt failure still rejects reload and keeps the previous snapshot.

## Unified permission rule engine foundation

- Added `docs/dev/designs/2026-05-01-unified-permission-rule-engine.md` as the new permission-rule design:
  - raw tool events are enriched into semantic requirements
  - rule decisions are evaluated per requirement and folded into one event decision
  - path read/list/write rules are first-class predicates, including `path_under`
  - normal user approval stays at `Allow once` / `Allow rule` / `Decline`
  - complex durable rules go through the owner-approved `add_permission_rule` tool
- Replaced command-only classification with `Nex.Agent.Sandbox.PermissionRule` enrichment and matching.
- Routed command approvals and interactive path approvals through the same rule engine.
- Added path rule support for allowing read/list-style access under a directory.
- Added `add_permission_rule` as a model-facing tool that creates a rule approval request without mutating rules before owner approval.
- Removed the legacy command classifier and old approval grant module/config fields from the command/path approval path.
- Updated the command permission skill and always-injected prompt guidance so the model can discover the richer rule flow when repeated command/path approval is useful.
