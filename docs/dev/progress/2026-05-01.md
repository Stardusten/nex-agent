# 2026-05-01

## Runtime fail-soft projection hardening

- Root cause: a workspace skill copied from a remote source used valid YAML `description: >-`, but `Skills.Loader` only accepted bare `>` / `|` block scalar headers. Runtime watcher crashed during skill reload instead of skipping the bad skill.
- Fixed `Skills.Loader` to:
  - parse `>` / `|` block scalar headers with optional `+` / `-` chomp indicators
  - skip a single invalid `SKILL.md` with a warning instead of failing the whole catalog
  - require model-facing `name` and `description` metadata to be strings
- Hardened `Runtime.Watcher` so skills/tools/runtime reload callbacks are isolated; callback failure logs a warning and the watcher keeps polling.
- Hardened `Runtime.build_snapshot/3` so non-critical projections use fail-soft fallback:
  - plugins
  - commands
  - subagents
  - skills
  - tool definitions by surface
  - hooks
  - Workbench app catalog
- Kept config/workspace resolution and prompt build as strong dependencies. Prompt remains the safety/identity-critical model input; prompt failure still rejects reload and keeps the previous snapshot.
